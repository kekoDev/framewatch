Your AI coding agent can't see the page it just built.

FrameWatch gives Claude Code a real browser. It sees the page, measures what it made, clicks through it, and fixes what it got wrong — before it says "done".

claude mcp add framewatch npx framewatch-mcp-server

Quick start

  1. Register it with Claude Code

    claude mcp add framewatch npx framewatch-mcp-server

  2. Let it see full results

    Claude Code caps a tool result at 25,000 tokens and counts images toward it, which holds about two screenshots of a real page. Raise it once, in the shell you start Claude Code from, and add the line to your shell profile.

    export MAX_MCP_OUTPUT_TOKENS=100000

  3. Start your app and ask

    Run your dev server as usual, open Claude Code in the project, and talk to it normally. It picks the tools itself.

    The header looks wrong on mobile. Check it at phone width and fix it.

    Open the settings page and tell me what you see.

  4. Sign in once, if your app has a login

    Ask Claude Code to log in and save the session. From then on every tool opens pages already signed in, and says so.

    Log in at localhost:5173/login with my test account and save the session.

Any other MCP client works too. Cursor, Windsurf, Claude Desktop and Zed take the same command in their MCP settings; the README has the JSON.

Eighteen tools, one browser

ToolWhat Claude Code uses it for
framewatch_screenshotWhat does this page look like right now?
framewatch_captureRecord a few seconds and keep only the frames where something changed — animations, loading, a replayed flow.
framewatch_interactClick, type, scroll, one action at a time, on a page that stays open between calls.
framewatch_snapshotEvery element on the page by name, with a ref to act on instead of a guessed selector.
framewatch_inspectBox, font, colours with WCAG contrast, spacing, alignment — or an inventory of the whole page's design values.
framewatch_wait_forReturn the moment Vite's hot update lands, a Vue app mounts, an element appears, or the network goes quiet.
framewatch_responsiveThe same page at phone, tablet and desktop widths, with overflow reported.
framewatch_accessibilityAn axe-core WCAG audit.
framewatch_compareTwo URLs, or before and after, with every differing pixel overlaid.
framewatch_form_testFill every form with valid, empty, huge, Arabic and hostile input and report what it did.
framewatch_seoWhat a search engine and a link preview make of the page, read from the rendered DOM.
framewatch_dead_clicksClick everything that looks clickable and report what did nothing.
framewatch_linksWhere every link goes: broken, redirected, refused, or pointing at no element.
framewatch_api_mockAnswer the page's API calls yourself — empty, 500, slow, malformed, offline — and record what it does.
framewatch_rtlFlip the page for Arabic, Hebrew or Persian and report what failed to mirror.
framewatch_save_authSign in once. Every later call starts past the login.
framewatch_start_server, framewatch_stop_serverBring the dev server up and down.

How it differs from a browser MCP

Only what changed

A browser MCP returns a screenshot per call. FrameWatch records at 10 frames a second and returns the handful where something meaningful happened, each cropped to the region that changed, each with the console output and requests from that moment.

Numbers, not impressions

"Looks fine" is not a check. Inspect returns the box, the font, the rendered colours with a WCAG verdict, the padding and the alignment to the neighbours, so the agent can compare what it built with what it meant.

Images that arrive

Claude Code drops a whole tool result that exceeds its token cap, images included. FrameWatch fits every result to the cap in a fixed order and says what it cut, so the agent always sees something.
